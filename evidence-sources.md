# Evidence Sources

## Overview

Before beginning the investigation, it is necessary to understand which evidence sources are available and what type of information each source can provide.

Security investigations should not begin by searching data without direction. Instead, the investigator should formulate a question and identify the most appropriate source of evidence to help answer it.

The evidence sources described below are relevant to the NorthWave Logistics laboratory environment.

---

## Evidence Sources Summary

| Source | What It Records | Questions It Can Help Answer | Limitations |
|---|---|---|---|
| `/var/log/auth.log` | Authentication and authorization events, including successful and failed logins, SSH sessions, sudo activity, PAM events, and user switching | Who attempted to authenticate? From which IP? Was the attempt successful? When did it occur? Was sudo used? Were there repeated failures? | Does not necessarily show what a user did after authentication. Evidence may be unavailable if logs are deleted or not properly configured. |
| `/var/log/syslog` | General system and service messages, including daemon activity, application errors, cron events, kernel messages, and other system events | Did a service restart? Were there unusual errors? What cron activity occurred? Was there an unexpected shutdown or reboot? | Can be highly noisy and contains events from multiple sources, requiring filtering and context. |
| `auditd` logs | Security-relevant audit events such as command execution, access to sensitive files, identity changes, system calls, and configuration modifications | What actions were performed after access was obtained? Were sensitive files accessed? Were configurations modified? Was a suspicious binary executed? | Requires prior configuration, may generate a large volume of data, and cannot provide historical evidence if it was not collecting events at the time. |
| Service logs | Service-specific activity such as SSH connections or events generated by internal applications | What client connected? What resource was requested? Which user performed an action? Was there unusual service activity? | Log formats and available details depend on the service and its logging configuration. |
| Process and network information | Current processes, open ports, active connections, and runtime information obtained through tools such as `ps`, `ss`, `lsof`, and `/proc` | Is a suspicious process currently running? Is a process listening on an unusual port? Is there an unexpected active connection? | Represents the current state and is volatile. It does not provide historical information unless the data was collected previously. |
| `cron` activity | Execution of scheduled tasks, typically recorded through system logging depending on the Linux distribution | What scheduled task executed? When did it run? Which user launched it? Did unusual scheduled activity appear? | May show that a task executed without showing everything the executed script actually did. |

---

## Evidence Types

Not all evidence sources are historical logs.

For this project, evidence can be grouped into three main categories:

| Evidence Type | Examples | Characteristics |
|---|---|---|
| Historical logs | `auth.log`, `syslog`, audit logs | Can provide information about events that occurred in the past. |
| Current system state | Processes, network connections, `/proc` | Volatile information representing the current state of the system. |
| Configuration | `crontab`, `sshd_config`, user accounts | Semi-static information that provides operational and security context. |

A security investigation may require combining multiple evidence types.

---

## Source Selection During an Investigation

The appropriate evidence source depends on the question being investigated.

For example:

- **Question:** Were there failed authentication attempts?  
  **Possible source:** `/var/log/auth.log`

- **Question:** Did a service restart or generate unusual errors?  
  **Possible source:** `/var/log/syslog`

- **Question:** What did a user do after obtaining access?  
  **Possible source:** `auditd` logs, if available and properly configured

- **Question:** Is there currently a suspicious process or network connection?  
  **Possible source:** Current process and network information

This reinforces an important principle of the investigation:

> The question should guide the selection of the evidence source.

---

## Project Decision

The primary evidence sources initially considered for this laboratory are:

- `/var/log/auth.log`
- `/var/log/syslog`
- Service-specific logs
- `cron` activity
- Current process and network information

`auditd` is considered a valuable evidence source but will be incorporated later if required by the investigation and laboratory environment.

The availability of each source will be evaluated as the project progresses.

---

## Key Takeaway

A SOC investigation should not rely on a single log source.

Different sources provide different perspectives on the same environment. Authentication logs may show how access occurred, system logs may provide operational context, audit logs may help explain what happened after access, and current system information may reveal active processes or connections.

Effective investigation requires selecting and combining evidence sources according to the questions that need to be answered.
